## 3. Сильные стороны

Чтобы было понятно, что **сохранять** при рефакторинге:

- **Нулевые runtime-зависимости.** Собственные генераторы PDF (с встраиванием TrueType, Identity-H
  и `/ToUnicode` — текст выделяется и ищется), EPUB 3 и DOCX, свой ZIP-писатель с CRC32. Это
  серьёзная инженерная работа, и она покрыта тестами.
- **Дисциплина «грязного» флага** (`isLoadingContent`, снапшоты `savedContent`/`savedMd`) —
  продумана и задокументирована в CLAUDE.md, ложных «Unsaved» почти нет.
- **Атомарная запись** (`atomic_write` через временный файл + `rename`) и **восстановление после
  сбоя** с явным выбором «восстановить / отказаться».
- **Миграции `.novel`** идемпотентны, и это закреплено тестами (`test/migrate-novel.test.js`):
  старые библиотечные файлы, главы без сцен, текстовые `relationships` — всё переносится.
- **Полная поддержка кириллицы** — в подсчёте слов (`\p{L}`), PDF, DOCX (`w:lang`), EPUB
  (`xml:lang`), с автоопределением языка романа.
- **Процесс разработки.** Мелкие PR со ссылками на issue, понятный `RELEASING.md`, релизный
  workflow с проверкой версии и черновиками релизов, CLAUDE.md с архитектурными инвариантами.
- **Комментарии объясняют «почему»**, а не «что» — редкость и большое подспорье для поддержки.

## 4. Безопасность

### 4.1 🔴 Критично: XSS из `.novel` → чтение и запись произвольных файлов

**Суть.** HTML сцены из файла без какой-либо очистки попадает в DOM. JS-код из файла выполняется с
полным доступом к `window.__TAURI__` (`withGlobalTauri: true`), а бэкенд-команды `write_text` /
`write_binary` / `read_text` принимают **любой путь** (п. 4.2). Значит, достаточно открыть
присланный кем-то `.novel` (бета-ридер, соавтор, «шаблон романа» из интернета), чтобы скрипт мог
прочитать или перезаписать любой файл пользователя, в том числе файлы автозапуска ОС. Это прямой
путь к выполнению кода.

**Подтверждено.** Сцена с содержимым `<img src=x onerror="...">` в браузерном режиме приложения
выполнила скрипт **трижды** просто при открытии файла: ещё до отрисовки (`migrateNovel` →
`stripHtml`), при загрузке в редактор и при подсчёте символов (`updateCounters` → `stripHtml`).
Цвет и иконка пользовательского типа заметки из файла дают ещё два срабатывания: список типов в
настройках рендерится сразу при открытии.

**Точки внедрения:**

| Где | Что не так |
|---|---|
| `app.js:282`, `app.js:1099` | `editor.innerHTML = s.content` — HTML из файла как есть |
| `app.js:35-37`, `1146-1147`, `4907-4909` | `stripHtml` / `htmlToMd` / `htmlToBlocks` парсят через `document.createElement('div').innerHTML`. У такого элемента «живой» документ-владелец, поэтому `<img onerror>` срабатывает, даже если элемент не вставлен в страницу. `stripHtml` вызывается уже в `migrateNovel` (`app.js:751`), то есть при открытии файла |
| `app.js:225` | `data-chapter-id="${c.id}"` — id из файла без экранирования |
| `app.js:1983`, `2090`, `2164`, `2188`, `2245` | `ty.icon` и `ty.color` (пользовательские типы заметок из файла) — в `innerHTML` без экранирования |
| `app.js:2244`, `2913` | `value="${ty.color}"`, `value="${ch.color}"` — выход из атрибута |
| `app.js:1998-2000` | `ty.color` вставляется в `<style>` — CSS-инъекция |
| `app.js:3399`, `3045` | `<option value="${l.id}">`, `<option value="${p.id}">` — id слоёв и пресетов без экранирования |
| `app.js:4138`, `4165-4166` | `font-family:${s.font}` из пресета компиляции — в атрибут `style`; превью компиляции вставляет HTML сцен через `innerHTML` |
| `app.js:1580` | экспорт в HTML переносит HTML сцен как есть (вредоносный код попадает в экспортированный файл) |

**Что сделать** (в порядке важности):

1. **Санитизировать HTML сцен по белому списку** при открытии файла (в `setCurrentNovel`, где
   есть DOM) и при вставке из буфера (п. 7.5). Надёжнее всего — подключить
   [DOMPurify](https://github.com/cure53/DOMPurify) одним файлом `src/vendor/purify.min.js` через
   `<script>`: это библиотека, а не фреймворк, и сборщик ей не нужен. Конфигурация — в п. 13.1.
2. **Парсить HTML только инертно**: заменить `document.createElement('div').innerHTML = …` на
   `new DOMParser().parseFromString(html, 'text/html').body`. Документ от `DOMParser` не загружает
   картинки и не выполняет обработчики (так уже сделано в `normalizeHTML`).
3. **Экранировать всё, что попадает в атрибуты**: `escAttr()` для id, цветов, значений. Цвета
   из файла дополнительно проверять регуляркой `^#[0-9a-f]{6}$` в `migrateNovel`, а шрифты
   пресетов — по белому списку.
4. Системно: перейти с `innerHTML`-шаблонов на хелпер, который экранирует подстановки
   автоматически (п. 9.2), — так этот класс ошибок исчезнет целиком.

### 4.2 🟠 Высокий риск: бэкенд пишет и читает любые пути

`read_text`, `write_text`, `write_binary` (`lib.rs:74-99`, `138-142`) принимают произвольный путь
от фронтенда. Пользовательские Tauri-команды в v2 доступны окну по умолчанию, capabilities их не
ограничивают. Даже после исправления XSS это лишняя поверхность атаки.

**Что сделать:** хранить в `tauri::State` набор путей, которые пользователь сам выбрал в диалоге
(`pick_open` / `pick_save`), плюс последний файл и недавние, и отклонять всё остальное. Эскиз — в
п. 13.4. Дополнительно можно описать собственные команды в app manifest
(`tauri_build::Attributes::app_manifest`) и выдавать окну только нужные.

### 4.3 🟠 CSP выключен

`tauri.conf.json:25` — `"csp": null`. В HTML нет inline-скриптов и атрибутов `on*=` (обработчики
навешиваются из JS), поэтому строгий CSP включается почти без правок. Готовая конфигурация — в
п. 13.3. Обратите внимание: `connect-src` должен включать `'self'`, иначе сломается `fetch` шрифтов
для PDF (`app.js:4501`). Для инжектируемых `<style>` (подсветка заметок, превью) нужен
`style-src 'unsafe-inline'`.

### 4.4 🟡 Средний риск: права окна шире нужного

`capabilities/default.json` выдаёт `core:default` (он уже включает `core:app/event/path/window:default`
— дублирующие строки можно убрать) и `dialog:default`. Фронтенду нужны только `event.listen`,
`window.onCloseRequested` / `onResized` и собственные команды. Лучше сократить права до явного
минимума: каждая лишняя разрешённая команда — это возможности для эксплойта из п. 4.1.

### 4.5 🟡 Цепочка поставок и подписи релизов

- В `release.yml` (с `contents: write`) действия закреплены по мажорным тегам (`@v7`, `@v1`), а не
  по SHA. Закрепите `uses:` по SHA и включите Dependabot для `github-actions`, `cargo` и `npm`.
- Сборки не подписаны, автообновления нет (это осознанно и описано в `RELEASING.md`). Для OSS
  есть бесплатная подпись под Windows (SignPath Foundation). Для macOS нужен Apple Developer ID.
  При добавлении автообновления `tauri-plugin-updater` проверяет собственную подпись обновлений,
  и для неё сертификат не нужен.

### 4.6 🟢 Мелочи

- `atomic_write` (`lib.rs:79-94`) не вызывает `File::sync_all()` перед `rename`. При отключении
  питания на некоторых ФС можно получить пустой файл. Добавьте `sync_all()` для временного файла.
  Права исходного файла тоже не сохраняются.
- При сбое между `write` и `rename` временный `.~tmp_*.tmp` остаётся рядом с романом и никем не
  удаляется.
- `config_dir()` (`lib.rs:9-16`) при ошибке откатывается на `"."` — тогда `working.novel` с
  полным текстом романа и `recent.json` запишутся в текущую рабочую папку процесса. Лучше
  вернуть ошибку.
- `add_recent_file` пишет через `fs::write`, а не атомарно.

## 5. Сохранность данных и надёжность

*(Отдельный раздел «от себя»: для редактора романов потеря текста — худший возможный баг.)*

### 5.1 🔴 Нет резервных копий и истории версий
Автосохранение раз в 30 с (`app.js:1666-1684`) **перезаписывает** `.novel` на диске. Удаление
сцены или главы — «This cannot be undone» (`app.js:345`, `417`), отмены структурных операций нет.
Случайно удалил главу → через 30 секунд она пропала и на диске.

**Что сделать:**
- Rust-команда `backup_rotate(path)`: перед каждой записью копировать текущий файл в
  `<app_data>/backups/<hash(path)>/<YYYY-MM-DD_HH-mm>.novel`. Хранить, например, последние 20
  копий плюс по одной за день на 30 дней. В меню — «File ▸ Restore from Backup…».
- «Корзина» для удалённых сцен и глав (`novel.trash[]`) с восстановлением; запросы
  подтверждения можно заменить тостом «Удалено · Отменить».
- Снимки сцены (как Snapshots в Scrivener) — см. 11.2.

### 5.2 🟠 Файл из более новой версии теряет данные при сохранении
`toFileObject` (`app.js:674-684`) записывает только известные ключи верхнего уровня, а `version`
всегда равен `'1.0'`. Если новая версия приложения добавит, например, `timeline` на верхний
уровень, а пользователь откроет файл в старой версии и сохранит — `timeline` молча исчезнет.

**Что сделать:** ввести целочисленный `schemaVersion` и цепочку миграций `vN → vN+1`. При
`schemaVersion > CURRENT` показывать предупреждение и/или открывать только для чтения.
`toFileObject` должен сохранять неизвестные ключи (`{ ...n, ...known }`).

### 5.3 🟡 `modifiedAt` сцены «врёт»
`saveCurrentScene` (`app.js:298`) обновляет `modifiedAt` безусловно, а вызывается он при каждом
переключении сцены, каждом бэкапе (раз в 10 с) и автосохранении. Даты на корк-борде показывают
«когда последний раз открывали», а не «когда правили». Обновляйте дату, только если `content`
действительно изменился.

### 5.4 🟡 Прочее
- Ошибка записи в `newNovelFile` (`app.js:923`) не перехватывается: unhandled rejection, пользователь
  не видит тоста, а в интерфейсе висит «созданный» файл, которого нет на диске.
- Подменю «Open Recent» в нативном меню строится один раз при запуске (`lib.rs:236-256`, `321-326`)
  и до перезапуска не обновляется.
- Картинка карты хранится в `.novel` как base64 (до ~16 МБ текста). Она раздувает файл и
  сериализуется при каждом бэкапе и автосохранении. Варианты: формат-папка или zip-контейнер
  (`project.novel/` с `assets/`), либо хотя бы кешировать сериализацию неизменившейся картинки.
- `guardUnsaved` (`app.js:884-887`) при открытии другого файла предлагает только «выбросить
  изменения / отмена». Нужен третий вариант «Сохранить и продолжить», как в диалоге закрытия.

## 6. Скорость работы

### 6.1 🔴 `stripHtml` квадратичен — до 0,4 с на нажатие клавиши
`stripHtml` (`app.js:35-60`) наращивает строку `text += …` и на каждом узле вызывает
`text.endsWith('\n')`. В V8 это каждый раз «сплющивает» растущую rope-строку, и сложность
становится O(n²). Обработчик `input` вызывает его **дважды** на каждое нажатие: напрямую и через
`updateCounters()`.

Замеры: Chromium headless, одна сцена, время обработчика `input` (медиана):

| Слов в сцене | Сейчас | `stripHtml` отдельно |
|---:|---:|---:|
| 2 000 | 1,6 мс | — |
| 10 000 | 12,4 мс | — |
| 30 000 | **446 мс** | 177 мс за вызов |

Тот же алгоритм на массиве частей (п. 13.2) даёт **2,6 мс вместо 177 мс** с побайтово
идентичным результатом. Заодно он парсит через `DOMParser` и закрывает вектор XSS из п. 4.1.
Сцена на 30 тыс. слов — редкость, но главы-сцены после импорта (п. 11.3) или вставки рукописи
целиком будут именно такими.

### 6.2 🟠 Слишком много работы на каждое нажатие клавиши
Обработчик `input` (`app.js:995-1008`) синхронно выполняет: сериализацию `innerHTML`, два
`stripHtml`, `countWords`, `normalizeHTML` (полный DOMParser с сортировкой атрибутов),
`reconcileNotes`, обновление счётчиков. Сохранить `s.content` и отметить «грязный» флаг можно
сразу, а подсчёт слов и символов, сравнение со снапшотом и пересчёт заметок — отложить через
debounce на 250–400 мс бездействия (п. 13.6).

### 6.3 🟠 Синхронные Tauri-команды в главном потоке
В Tauri v2 команды без `async` выполняются **в главном потоке**. Поэтому:
- `pick_open` / `pick_save` вызывают `blocking_pick_file` / `blocking_save_file` в главном потоке,
  а документация `tauri-plugin-dialog` прямо говорит не делать этого (риск зависания, особенно на
  Linux/GTK);
- запись многомегабайтного `.novel` (с картой) блокирует цикл событий окна.

**Что сделать:** объявить файловые команды и диалоги как `async fn` (они уйдут в пул потоков), а
тяжёлую запись обернуть в `spawn_blocking` (п. 13.5).

### 6.4 🟡 Прочее
- **Бинарные данные через base64.** `write_binary` получает base64-строку (+33 % объёма, плюс
  JSON-сериализация IPC) и декодирует её самописным декодером. В Tauri v2 есть сырой бинарный IPC
  (`tauri::ipc::Request` с `InvokeBody::Raw`): `invoke('write_binary', bytes, { headers: { path } })`.
- **ZIP без сжатия** (`makeZip`, только store). EPUB и DOCX получаются в разы больше нужного.
  `CompressionStream('deflate-raw')` есть в актуальных WebView2 и WebKit — сжимайте всё, кроме
  `mimetype`.
- **PDF встраивает шрифты целиком** (≈140 КБ × до 3 начертаний). Сабсеттинг (только
  использованные глифы — они уже собираются в `report.used`) сократит файл в несколько раз.
- **Бэкап каждые 10 с** сериализует весь роман, даже если с прошлого бэкапа ничего не
  изменилось. Достаточно счётчика ревизий: бэкапить, только если `rev !== lastBackupRev`.
- **Шесть глобальных обработчиков `mousemove`** (дерево, корк-борд, компиляция, фокус-режим, граф,
  карта) срабатывают на каждое движение мыши, даже когда ничего не перетаскивается. Подключайте их на `mousedown` и снимайте на `mouseup`.

## 7. Удобство (UX)

### 7.1 🔴 Хоткеи не работают на русской раскладке
Обработчик клавиш (`app.js:5090-5115`) сравнивает `e.key === 's'`, `'o'`, `'g'`, `'\\'`, `'/'`.
При русской раскладке `e.key` равен `'ы'`, `'щ'`, `'п'`… Исключение сделано только для `Ctrl+Shift+M`
(`'ь'`). Часть хоткеев на Windows и macOS спасают акселераторы нативного меню, но у `Ctrl+G`,
`Ctrl+\`, `Ctrl+/` пунктов меню нет, и в браузерном режиме не работает ничего. Для приложения,
которое явно рассчитано на русскоязычных авторов, это заметно.
**Что сделать:** сравнивать `e.code` (`'KeyS'`, `'KeyG'`, `'Backslash'`, `'Slash'`) — п. 13.7.

### 7.2 🟠 Минимальный размер окна не помещается на типичных ноутбуках
`minWidth: 1200, minHeight: 750` (`tauri.conf.json:17-18`). На 1366×768 с панелью задач Windows
доступно ~728 px по высоте, а на очень распространённом 1920×1080 при масштабе 150 % — 1280×720
логических пикселей. Окно не влезает в экран. Уменьшите минимум до ~900×600 и добавьте
автосворачивание боковых панелей на узких окнах (п. 8.4).

### 7.3 🟠 Нет поиска и замены
В текстовом редакторе для романов это базовая функция, подробнее — в 11.1.

### 7.4 🟠 Модальные окна
- `confirmModal` / `promptModal` (`app.js:1440-1468`) не закрываются по `Esc`, у подтверждения
  нет `Enter`, фокус не удерживается внутри окна и не возвращается после закрытия.
- «About» сделан через `confirmModal` и показывает бессмысленную кнопку «Cancel» (`app.js:5141`).
- Один глобальный `modalCb`: второй вызов модалки, пока открыта первая, молча её подменяет.

### 7.5 🟠 Вставка из Word и браузера приносит мусор
Обработчика `paste` нет, поэтому `contenteditable` принимает чужие стили, `span`, классы, шрифты и
картинки. Добавьте обработчик: чистить вставку тем же санитайзером из 4.1, а `Ctrl+Shift+V`
сделать «вставкой без форматирования».

### 7.6 🟡 «Typewriter focus (dim & center)» не делает обещанного
Переключатель (`index.html:275-278`) только добавляет отступы 30vh сверху и снизу редактора, и то
лишь в фокус-режиме (`styles.css:269`). Не происходит ни затемнения неактивных абзацев, ни
удержания каретки по центру. Реализация: на `selectionchange` прокручивать `.editor-scroll` так,
чтобы каретка оставалась на ~40 % высоты, а текущему блоку давать класс `.is-current` при
`opacity: .35` у остальных.

### 7.7 🟡 Экспорт PNG графа и карты идёт мимо диалога сохранения
`exportGraphPng` и `exportMapPng` (`app.js:2993-3000`, `3527-3533`) используют `<a download>`.
В Tauri это не показывает диалог сохранения и, в зависимости от webview (WKWebView, WebKitGTK),
может вовсе не сработать. Все остальные экспорты уже идут через `pick_save` + `write_binary` —
сделайте так же (`canvas.toBlob` → байты → `saveBinary`).

### 7.8 🟡 Интерфейс только на английском
Целевая аудитория пишет на русском (типы заметок изначально были русскими, есть автоопределение
языка). При этом весь UI английский, а даты заметок жёстко форматируются в `'en-US'`
(`app.js:1851`). Предложение — простой словарь `i18n = { en: {...}, ru: {...} }` и функция
`t('key')`. Язык интерфейса — в настройках, по умолчанию `navigator.language`.

### 7.9 🟡 Качество компиляции
- **PDF превращает «—» в «-», «…» в «...», а “ ” в "** (`normalizeForPdf`, `app.js:4318-4333`), хотя
  встроенный IBM Plex Mono содержит все эти глифы (проверено). В русской прозе тире открывает
  каждую реплику, и диалоги в PDF выглядят как «- Привет, - сказал он». Комментарий в коде
  остался с тех времён, когда PDF собирался на стандартных шрифтах без кириллицы. Сейчас свёртку
  можно убрать.
- **Шрифт из настроек компиляции игнорируется в PDF**: там всегда моноширинный Plex Mono. Либо
  подпишите это в интерфейсе («PDF: моноширинный, стандарт рукописи»), либо встройте
  пропорциональную антикву с кириллицей (PT Serif, Literata, Noto Serif — все под OFL) и
  считайте ширину по `hmtx`. Тогда станут доступны и выравнивание по ширине, и переносы.
- **DOCX** — минимальный пакет без `styles.xml`: шрифт, поля (`app.js:5013` — всегда 1440) и
  нумерация страниц из настроек не применяются. Заголовки не оформлены стилями Heading 1/2,
  поэтому в Word не работают навигация и автособираемое оглавление.
- **EPUB** — весь роман в одном `book.xhtml`. На читалках длинный единый файл открывается
  медленно; лучше файл на главу. Обложки нет.

### 7.10 🟡 Отмена действий
Undo опирается на нативный стек `execCommand`, который сбрасывается при каждом
`editor.innerHTML = …` — то есть при переключении сцены. Структурные операции (удаление и
перемещение сцен, правки персонажей, карты) не отменяются вообще. Минимум: собственный стек
команд для структурных операций плюс «Отменить» в тостах удаления.

### 7.11 🟢 Мелкие несоответствия
- При первом открытии графа роман помечается «грязным» (`ensureGraphPositions`, `app.js:2594`) —
  это противоречит правилу из CLAUDE.md «не помечать dirty при открытии панелей».
- Плейсхолдер редактора — «Start writing your chapter…» (`styles.css:259`), пустой список
  заметок — «No notes in this chapter» (`app.js:2176`), хотя редактируется **сцена**.
- В `index.html:285-289` статическое содержимое `#ctxMenu` (Rename/Duplicate/Delete) никогда не
  используется: меню каждый раз пересобирается в JS.

### 7.12 🟡 Подсчёт слов считает « - » словом
`countWords` (`app.js:31-34`) использует `/[\p{L}\p{N}'’-]+/gu`, поэтому одиночный дефис,
которым многие набирают тире, считается словом:

| Текст | Сейчас | Исправлено |
|---|:-:|:-:|
| `Привет - мир` | 3 | 2 |
| `Он сказал - нет - и ушёл` | 7 | 5 |
| `кто-то`, `rock'n'roll` | 1 | 1 |

Исправление: `/[\p{L}\p{N}]+(?:['’-][\p{L}\p{N}]+)*/gu` — слово должно начинаться и
заканчиваться буквой или цифрой.

### 7.13 🟢 Нативное меню на macOS (проверить на Mac)
На macOS первое подменю в строке меню становится меню приложения. Сейчас первым идёт «File»
(`lib.rs:258`), поэтому его пункты, вероятно, окажутся под заголовком «NovelCraft», и не будет
стандартных Hide/Services/Quit. Обычно на macOS добавляют отдельное подменю приложения под
`#[cfg(target_os = "macos")]`.

## 8. Визуальная часть

### 8.1 Одна тема и захардкоженные цвета
Тема только тёмная. В `styles.css` и `app.js` (44 hex-литерала, в том числе вся отрисовка canvas:
фон графа `#1a1a1f`, сетка `#2a2a35`, подписи `#e8e0d5`…) цвета заданы напрямую, мимо токенов `:root`.
**Шаги:** вынести всё в CSS-переменные (canvas читает их через `getComputedStyle`); добавить
светлую и «сепию» темы через `[data-theme]`; уважать `prefers-color-scheme`. Писатели часто
работают днём при ярком свете, и тёмная тема там утомляет.

### 8.2 Эмодзи вместо иконок
📁 🎬 📋 🗺️ 🔗 📝 ⚙️ 🗑 ✏️ 🩹 — на Windows (Segoe UI Emoji), macOS (Apple Color Emoji) и Linux
(Noto или вовсе квадратики) они выглядят по-разному и не наследуют цвет темы. Небольшой
SVG-спрайт (например, 30 иконок Lucide, лицензия ISC) в `src/icons.svg` + `<svg><use href>`
даст единый вид и `currentColor`.

### 8.3 Шрифты из меню на самом деле не поставляются
Меню предлагает Lora, Merriweather, Inter и Roboto, но `.woff2` в репозиторий не входят
(`.gitignore`), а `npm run fonts` **не скачивает ни одного файла**:
1. С User-Agent из скрипта (`fetch-fonts.mjs:20`) Google Fonts отдаёт `.ttf`, а регулярка
   (`fetch-fonts.mjs:27`) ищет только `.woff2` → «No woff2 found».
2. С браузерным User-Agent первым в CSS идёт сабсет `cyrillic-ext`, в котором нет ни латиницы,
   ни обычной кириллицы.

Даже скачанный Lora содержит только начертание 400, хотя `@font-face` объявляет `400 700`
(жирный будет синтезирован). В итоге у пользователей вместо Lora/Merriweather почти всегда
Georgia или системный шрифт.
**Что сделать:** положить в `src/fonts/` полные woff2 (например, из npm-пакетов `@fontsource/*`
или из `google/fonts` на GitHub) с кириллицей и нужными начертаниями, закоммитить вместе с OFL и
удалить скрипт. Для писательского приложения стоит добавить ещё 1–2 «книжных» шрифта с хорошей
кириллицей: Literata, PT Serif, EB Garamond.

### 8.4 Нет адаптивности
В `styles.css` нет ни одного `@media`. Панели жёстко 250 и 300 px. Предложения:
перетаскиваемые разделители панелей (ширина в prefs); автосворачивание правой панели при ширине
окна < 1100 px.

### 8.5 Доступность (a11y)
- `.control:focus{outline:none}` и `.editor{outline:none}`, у кнопок нет `:focus-visible` —
  с клавиатуры не видно, где фокус.
- Выпадающие меню и контекстные меню не управляются стрелками и `Esc`.
- Нет `prefers-reduced-motion`, а анимаций переходов много.
- `--text-dim` (#8f887c) на `--panel` (#22222b) — контраст на грани AA (~4.5:1). Для
  второстепенного текста 11 px лучше чуть светлее.

### 8.6 Типографика редактора
Сейчас доступны только размер (14–24) и шрифт. Чего не хватает автору: ширины колонки текста
(`max-width` 820 px захардкожен), межстрочного интервала, абзацного отступа вместо интервала
(«книжный» вид), выравнивания по ширине с `hyphens:auto` и атрибута `lang` у редактора по языку
романа (влияет и на переносы, и на проверку орфографии).

### 8.7 Мёртвый CSS
Остатки модели «библиотека романов», которые нигде не используются: `.chapter-title`
(`styles.css:48-52`, `81`), `#novelsSection` (`155-156`), `.lp-collapse` и `.lp-section.collapsed`
(`160-165`), `.novel-list`/`.novel-item`/`.ni-title`/`.ni-meta` (`167-177`). Удалить.

## 9. Кодстайл и архитектура

### 9.1 Монолит `app.js`
5 249 строк: 98 глобальных `let`/`const` и 308 функций верхнего уровня, общее изменяемое
состояние в глобальных переменных (`novel`, `dirty`, `mdMode`, `comp`, `gView`, `mView`…).
Тесты вынуждены вырезать функции по маркерам-комментариям и склеивать куски (`migration-core:*`
собирается из четырёх фрагментов) — это хрупко.

**Предложение:** нативные ES-модули — **без сборщика**, это совместимо с философией проекта.
`<script type="module" src="app/main.js">`, webview Tauri грузит их напрямую. Тогда тесты
делают обычный `import { migrateNovel } from '../src/app/model/migrate.js'`, и маркеры не нужны.
Примерная раскладка:

```
src/app/
  main.js              — запуск, связывание модулей
  core/dom.js          — $, $$, el(), html``, esc, escAttr
  core/state.js        — store: novel, currentSceneId, dirty, ревизии, подписки
  core/tauri.js        — invoke/listen + браузерный фолбэк
  model/novel.js       — newNovel, blankScene/Chapter, schema
  model/migrate.js     — migrateNovel + цепочка миграций
  text/html.js         — sanitize, stripHtml, htmlToMd, mdToHtml, countWords
  editor/*.js          — редактор, тулбар, markdown-режим, заметки
  views/tree.js, corkboard.js, graph.js, map.js, compile.js
  export/pdf/*.js, epub.js, docx.js, zip.js, txt.js
  ui/modal.js, toast.js, menu.js, shortcuts.js
```

Минус: браузерный режим с `file://` перестанет работать, потому что модули по `file://`
блокируются CORS. Нужен локальный сервер (`npx serve src`), а это одна строка в README/`npm run web`.

### 9.2 `innerHTML`-шаблоны
72 места с `innerHTML`, экранирование — вручную и местами пропущено (п. 4.1). Небольшой
tagged template, экранирующий подстановки по умолчанию, убирает класс ошибок целиком (п. 13.8).

### 9.3 Дублирование

заменить его в одном месте. В дальней — модель документа (например, ProseMirror: его можно
положить в `vendor/` как ESM без сборщика) с нормальным undo, схемой и вставкой.

## 11. Новые фичи

Отсортированы по ценности для автора романа.

### Обязательно

**11.1 Поиск и замена.** `Ctrl+F` — по текущей сцене, `Ctrl+Shift+F`/кнопка — по всему роману
(сейчас это сочетание занято фокус-режимом, его можно перенести на `F11`). Опции: регистр,
целое слово, регулярные выражения. Результаты — список «Глава › Сцена · фрагмент», подсветка через
CSS Custom Highlight API (уже используется для заметок, `app.js:1993-2023`). После замены — вызов
`reconcileNotes`, чтобы заметки не «поехали».

**11.2 Снимки сцены и история версий.** «Сделать снимок» перед большой правкой; список снимков с
датой и сравнением (diff по словам) и восстановлением. Вместе с 5.1 это закрывает страх
«испорчу текст».

**11.3 Импорт.** TXT, Markdown и DOCX (DOCX — это ZIP с XML, а разбор ZIP почти готов) с
разбиением на главы и сцены по заголовкам или разделителю `* * *`. Без импорта перейти в
NovelCraft с существующей рукописью почти невозможно.

**11.4 Типограф для русского текста** (переключаемый, зависит от языка романа):
`"` → «ёлочки» (и „лапки“ внутри), ` - ` и `--` → ` — `, `...` → `…`, неразрывный пробел после
тире в начале реплики и перед `—`. Для `en` — “ ” и ‘ ’.

**11.5 Цели и статистика.** Дневная цель слов, сессия (таймер, «+N слов за сессию»), серия дней
подряд, график по дням (`novel.settings.stats = { 'YYYY-MM-DD': words }`), дедлайн с расчётом
«сколько слов в день нужно». Для писателей это один из главных мотиваторов.

**11.6 Синопсис сцены и режим «план» (Outline).** Поле `synopsis` у сцены, которое показывается на
карточке корк-борда (сейчас там только метаданные). Табличный вид: сцена / POV / локация / статус
/ слова / синопсис с сортировкой и правкой прямо в таблице.

### Желательно

- **Темы**: светлая, сепия (п. 8.1). **Локализация** интерфейса (п. 7.8).
- **Экспорт в FB2** — основной формат русскоязычного рынка электронных книг (принимается
  крупными площадками для самиздата). Это простой XML поверх уже существующего `compFlow()`.
- **Таймлайн**: у сцен есть `timeOfDay`, но нет даты или дня истории. Добавить
  `storyDay`/`storyDate` и горизонтальную ленту сцен по POV-дорожкам.
- **Теги и метки сцен** (сюжетные линии, цвета) с фильтром в дереве и на корк-борде; несколько
  POV у сцены.
- **Упоминания персонажей и локаций**: «появляется в сценах…» в карточке персонажа (поиск имени и

- **Разделённый экран**: справочная сцена или карточка персонажа рядом с редактируемой сценой.

### 13.2 Линейный и безопасный `stripHtml` (проверен: идентичный вывод, 177 → 2,6 мс)

```js
const parseInert = html => new DOMParser().parseFromString(html || '', 'text/html').body;
const BLOCK_TAGS = new Set(['P', 'DIV', 'H1', 'H2', 'H3', 'H4', 'H5', 'H6', 'LI', 'BLOCKQUOTE', 'TR', 'UL', 'OL', 'TABLE']);
const stripHtml = html => {
  const parts = [];
  let last = '';
  const push = s => { if (s) { parts.push(s); last = s[s.length - 1]; } };
  const walk = node => {
    if (node.nodeType === 3) { push(node.nodeValue); return; }
    if (node.nodeName === 'BR') { push('\n'); return; }
    const isBlock = BLOCK_TAGS.has(node.nodeName);
    if (isBlock && parts.length && last !== '\n') push('\n');
    for (const c of node.childNodes) walk(c);
    if (isBlock && parts.length && last !== '\n') push('\n');
  };
  walk(parseInert(html));
  return parts.join('').trim();
};
// То же parseInert() — в htmlToMd() и htmlToBlocks() вместо document.createElement('div').
```

### 13.4 Белый список путей в Rust

```rust
use std::{collections::HashSet, path::{Path, PathBuf}, sync::Mutex};

#[derive(Default)]
struct Granted(Mutex<HashSet<PathBuf>>);

/// Ключ для сравнения: канонический путь (для ещё не созданного файла — канонический родитель + имя).
fn key(p: &Path) -> PathBuf {
    p.canonicalize().unwrap_or_else(|_| match (p.parent(), p.file_name()) {
        (Some(dir), Some(name)) => dir.canonicalize().unwrap_or_else(|_| dir.into()).join(name),
        _ => p.into(),
    })
}
fn grant(state: &Granted, p: &Path) { state.0.lock().unwrap().insert(key(p)); }
fn granted(state: &Granted, p: &str) -> Result<PathBuf, String> {
    let path = PathBuf::from(p);
    if state.0.lock().unwrap().contains(&key(&path)) { Ok(path) } else { Err("path not allowed".into()) }
}

#[tauri::command]
async fn write_text(state: tauri::State<'_, Granted>, path: String, content: String) -> Result<(), String> {
    let path = granted(&state, &path)?;
    tauri::async_runtime::spawn_blocking(move || atomic_write(&path.to_string_lossy(), content))
        .await.map_err(|e| e.to_string())?.map_err(|e| e.to_string())
}
// pick_open / pick_save / get_last_file / пункты «recent:» вызывают grant() для выбранного пути.
// builder: .manage(Granted::default())
```
